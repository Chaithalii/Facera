The Problem

A face is not a name. The challenge is building a system that reliably bridges the gap — even under imperfect conditions.

Facera is a modular face recognition identification system built with InsightFace and ONNX Runtime. Given a query image, it detects every face, extracts a 512-dimensional ArcFace embedding, and compares it against an enrolled database using cosine similarity.

When the best match score exceeds a configurable threshold, the person is identified. When it does not, the face is rejected as Unknown — an honest acknowledgement of the system's limits rather than a forced guess.

How it works.

Four-stage pipeline
01
Detect

Face Detection

RetinaFace scans the input image using a multi-scale Feature Pyramid Network. It outputs bounding boxes and five facial landmark points per face — regardless of scale or partial occlusion.

det_10g.onnx det_score ≥ 0.50 640 × 640 input
02
Align

Landmark Alignment

The five detected landmarks (eye centres, nose tip, mouth corners) drive an affine warp that maps the face to a canonical 112 × 112 crop. Eyes and mouth land at fixed pixel coordinates, removing pose variation.

112 × 112 crop Affine transform 5-point geometry
03
Embed

ArcFace Embedding

The aligned crop is fed to ArcFace-R50, a ResNet-50 trained with angular margin loss on 600 K identities. The network outputs a 512-dimensional vector, L2-normalised to unit length.

w600k_r50.onnx 512-d, L2-normed WebFace600K
04
Decide

Threshold Decision

Cosine similarity is computed against every enrolled embedding. The highest scorer wins. If that score meets or exceeds the configured threshold, the person is identified. Otherwise: Unknown.

cosine_sim = dot product threshold: configurable default: 0.35
Input Image  → RetinaFace  → Landmark Warp  → ArcFace-R50  → Cosine Similarity  → Identified  / Unknown

Enrollment

Teaching the system a face.

Enrollment extracts and aggregates ArcFace embeddings from multiple images of one person, producing a single representative 512-d vector stored in the database.

More images reduce per-image noise — expression, lighting, and distance variation all get averaged out into a stable identity signature.

Aggregation Strategy

Each per-image embedding is extracted individually, then averaged (or median-reduced) and re-normalised. The database stores one unit-norm vector per person — fast for lookup, robust from variation.

Recommendations

Use 5–10 images per person for best robustness
Vary lighting, angle, and expression slightly
Ensure face is clearly visible, not blurred
Only the highest-confidence face per image is used

Threshold

Finding the right cutoff.

The threshold separates genuine pairs (same person, different images) from impostor pairs (different people). No threshold is arbitrarily optimal — it must be calibrated on your actual data.

The chart plots estimated probability density for each distribution. Drag the threshold line to see how FAR (False Acceptance Rate) and FRR (False Rejection Rate) trade off.

The Equal Error Rate (EER) is the threshold where FAR = FRR — the data-driven starting point. Run calibration to find it for your dataset.

Where it fails.

An honest account of failure modes. Every production face recognition system should document these — not hide them.

Scenario Detection Identification Notes
Poor lighting
 May fail N/A
RetinaFace needs minimum pixel contrast. Very dark or overexposed images often produce no detections.
Motion blur
 Partial Degraded
Blur corrupts the 112×112 crop fed to ArcFace, lowering embedding quality and similarity scores.
Side profile (>60° yaw)
 Partial Usually Unknown
ArcFace was trained on near-frontal images. Extreme yaw significantly degrades embedding quality.
Face mask
 Usually OK Degraded
Eyes visible → landmark alignment still possible. But occluded mouth removes discriminative features.
Very small face (<30 px)
 Fails N/A
RetinaFace with 640×640 input has a practical minimum face size. Small faces at distance are missed.
Multiple faces
 All detected Each processed
System correctly detects and identifies all faces independently. Handled correctly.
Unknown person
 Detected Rejected
Threshold mechanism works as designed. Score below threshold → "Unknown" returned.
Sunglasses
 May detect Severely degraded
Eye landmarks are critical for alignment. Sunglasses obstruct landmark estimation and corrupt the crop.
Identical twins
 Detected May confuse
Near-identical ArcFace embeddings. Cosine similarity between twins is high enough to cross the threshold.
Different expressions
 Detected Usually correct
ArcFace is reasonably robust to expression changes. Extreme expressions may reduce similarity slightly.
Roadmap

Future improvements.

Every system has a version 2. These improvements would move Facera from a research prototype toward a production-hardened system.

1

Multiple embeddings per person

Store N embeddings per enrolled person (one per image) and use nearest-neighbour search across all, rather than a single aggregate vector. Improves robustness to intra-class variation without losing accuracy.

2

Anti-spoofing (liveness detection)

Add a passive liveness detection model (e.g. Mini-FASNet) to reject printed photos, screen replays, and 2D masks before embedding extraction. Critical for any security-facing deployment.

3

FAISS approximate nearest-neighbour search

Replace O(N) linear scan with a FAISS index for sub-millisecond retrieval across databases of tens of thousands of enrolled persons.

4

Profile and multi-pose support

Integrate a separate profile-face embedder trained on multi-pose data, or use 3D face fitting to synthesise frontal views from extreme angles before embedding.

5

GPU acceleration

Switch to CUDAExecutionProvider in config.py for 10–50× faster inference. Enables real-time processing of high-resolution video streams.

6

Incremental enrollment & drift adaptation

Allow adding new images to an existing enrollment without rebuilding the full database. Periodically update representative embeddings to account for appearance changes over time (aging, hairstyle changes).
